# 给ChatGPT / 自动化代理的执行合同（Reference ClipFlow）

请先阅读 README.md，再执行以下约束。**不要把开发能力等同于任意聊天账号已具备本地命令执行权限**。

## 极简调用与自动阶段选择

- 用户只说“执行 ClipFlow”时，**按已上传素材自动判别阶段**：单个对标视频执行下方“对标视频”流程；一组待合成新片段执行“新视频片段”流程。不要要求用户重复背诵规则。无法辨别输入身份或顺序且无法用实际媒体判断时，才询问必要信息。
- 同账号/已装环境：**先复用可用的最新版程序和依赖**；缺失或版本落后时，才从已连接的公开 GitHub 读取/更新。其他账号：先读取本项目 `README.md`、`AGENTS.md`，检测可执行环境，缺依赖才安装。只有阅读权限而无代码执行能力时，必须说明限制。
- 提示词与安装入口统一收敛在 `PROMPT_FOR_CHATGPT.md`。**细节只维护本文件与 `README.md`**；不得因为启动词缩短，省略镜头、ASR、逐段台词、水印、字幕对标优先、默认调色、可选项门禁、验证或交付。

## 用户直接上传“对标视频”

默认一并执行原先功能①②③：镜头/人物和对白时间分析、每段≤10秒切分、C方案001…编号水印（文本alpha 40%、黑描边alpha80%、横屏10px/竖屏7px），自动生成完整原视频SRT。**首要交付一个 `ClipFlow_完整交付.zip`**，内部包含 segments/ 所有编号MP4、captions.srt、segments_transcript.md（每段一节台词，只在段标题列起止时间）、manifest.json、segments_list.csv、subtitle_samples/（联系表及原帧字幕样张）、subtitle_style_profile.json；以及 `segment_stills/001_镜头.jpg` 等每段一张开头干净截图；旧版两个拆分ZIP仅为兼容保留。程序必须在交付前读回ZIP检查CRC、成员、非空、数量与编号，并仅对真实存在、可下载的文件提供链接。使用 `clipflow reference --input ... --out ...`；先确认ASR可用，否则明确说明需安装依赖/使用用户已校对SRT。不要伪称已经ASR识别。

**无画面字幕时的ASR为正式功能**：省略 `--srt` 即从对标视频的原声音轨运行 faster-whisper，优先使用词级时间戳，生成全文SRT并自动按最终分段把台词写进 `segments_transcript.md`（同时写入manifest逐段`transcript`字段）。若没有词级时间戳，或者使用了传入的SRT，则按字幕范围做比例估算并在MD注明。首次安装ASR：`python -m pip install -e '.[asr]'` 或 `python scripts/setup_asr.py --model small`；`clipflow doctor` 可检查依赖是否存在。安装依赖失败/模型不可用/无音轨时明确停止，不编造识别结果。单独语音转文字可用 `clipflow transcribe --input ... --out ...`。不要把“给定SRT”写成“已执行ASR”。

人物身份、机位角度、复杂特效不可能仅靠颜色帧差百分之百判定；需要核对片段和句尾。如果用户要求角色标签，请通过观察/模型判断后写入manifest，不要伪造。

## 用户随后上传多个“新视频片段”

**默认只执行：自动识别顺序 → 拼接全部画面 → 去灰通透近似调色**。默认不做原声替换、默认不压制字幕。用 `clipflow assemble --clips-dir ... --out ...`。

当用户给了随机文件名时，先用原视频音频匹配；不能匹配则请求/提供 `order.txt`，不可凭生成时间乱序拼接。

如果用户尚未声明是否需要可选功能，可以一句话问“需要原声替换、字幕合成吗？默认均不做。”；**不要因此擅自执行这两个功能**。若用户已经明确只拼接或已经给出“拼接+替换+字幕”完整指令，不重复确认。

用户明确要求原声替换，才增加 `--replace-audio --reference ...`；明确要求字幕合成，才增加 `--burn-subtitles --srt ...` 或 `--manifest ...`。两者互相独立，均可同时启用。检查新视频是否已有硬字幕，避免重复压字。

## 对标字幕还原优先规则（高于任何历史固定字模）

- 第一阶段务必查看原视频有无真正的画面字幕（不是单凭音轨或ASR推断）。阅读 `subtitle_samples/subtitle_reference_contact.jpg`，必要时逐张打开同目录**原分辨率截图**；不能确定时追加取样。
- **有字幕**：尽力逐细节复刻：字形/最相似授权字体、粗细、比例字号、字距、显示区域、横纵偏移、单/双行、边框粗细、描边颜色和透明度、阴影、每一条字幕的常规颜色与特殊词颜色/大小、入场退出时机。特别注意颜色按具体字幕变化。不要套用固定C/B/B、84px、黄绿色高亮关键词。
- 用视觉结论填写 `subtitle_style_profile.json`，设 `reference_has_subtitles=true`、`visually_reviewed=true`，按样张配置基础值以及 `caption_styles` 的每条例外。必要时做“对标帧/合成帧”两三组并排校对。字体名字不能直接反推出时，记录近似并使用当地合法可用的最接近字体，不得夸大完全相同。
- **无字幕**：确认后设置 `reference_has_subtitles=false`、`visually_reviewed=true`，允许使用之前的后备方案：特粗黑体或粗宋、普通84px重点94px（以1080竖屏为参照）、白色+黄绿色强调、黑描边、3px字距、中下偏上等。长句缩放防超边。
- **未经视觉审核**：配置中 `reference_has_subtitles=null`、`visually_reviewed=false` 时，禁用字幕合成并提示先审核，禁止悄悄使用B字模。第一阶段做编号ZIP+SRT不受此限制；第二阶段未要求字幕时也不需要审核。
- 如新片段自带硬字幕，不允许二次叠字；如用户要求去掉既有硬字幕，应另行确认处理方案，不能擅自裁切或涂抹。

## 固定设计

- 水印：用户选定C粗描边；不要自动改回B，不要降低40%填充与80%描边alpha。
- 调色：后期合并时默认模拟“去灰通透”，**不是剪映同名原生滤镜**。
- 编码：保留输入分辨率/帧率；**不默认做60帧高清重制/AI补帧**。
- 安全：原素材、字幕、用户音轨只能保留在用户作业目录；禁止提交GitHub。
- 输出：第一阶段首要交付单一完整ZIP，内含分段MP4、SRT、每段一条台词的MD、切分清单、字幕样张。检查ZIP成员、CRC、数量、大小，确认沙箱/附件真实存在后给下载链接；未运行成功不能声称完成。
- **开头截图（v0.4.2新增）**：第一阶段每个片段必须输出一张 `segment_stills/NNN_镜头.jpg`，编号和MP4一一对应。从原始对标视频对应片段起点的前0.6秒／最多20帧中，优先选择不黑场、不闪白、清晰和稳定的原始帧；保持原分辨率，不裁剪、不调色、不添加编号水印。内嵌原字幕或原场景内容保留。`manifest.json`应记录截图文件、原视频帧编号和时间。算法只能做清晰度／曝光技术筛选，不能保证人脸一定睁眼或没有表情瑕疵，需要抽查。缺一张截图或编号不匹配，禁止交付ZIP。


## 云端ASR执行门禁（v0.4.0）

- **优先复用已获授权的云端ASR服务**：运行环境具有`CLIPFLOW_ASR_URL`与`CLIPFLOW_ASR_API_KEY`时，才允许向这个明确配置的服务上传抽取后的音频块；否则走本地faster-whisper。若用户明确指定本地，使用`--asr-backend local`，不能自动上传。
- 云端只传音频FLAC小块，不传视频画面或整个视频ZIP；密钥放在安全环境变量，禁止存放在GitHub、文档、提示词、常规日志。没有授权域名/密钥/网络时明确报告阻塞，不自行换提供商。
- 交付仍为第一阶段的`numbered_segments.zip`＋`captions.srt`＋`segments_transcript.md`；第二阶段默认拼接去灰，原声替换与字幕压制只有明确要求才开启。
- **三个层级必须分开验收**：本地代码及协议测试、云端模型实际部署与受保护访问、真实中文口播转写及SRT/逐段MD验证。付费计划/密钥配置/跨账号授权需要相应批准。不能把模拟测试称为真实Whisper或生产就绪。
