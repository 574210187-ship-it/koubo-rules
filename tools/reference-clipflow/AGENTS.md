**用户最新决定：只执行第一阶段。** 当前窗口、新ChatGPT窗口和自动化执行入口仅领取**对标原视频切分**任务，生成完整`ClipFlow_完整交付.zip`及ZIP外独立`文案.txt`，并把本次实际对外交付的全部文件回填同一条飞书记录的指定多附件格。不再调用第二阶段，不做新片段拼接、后期调色、原声替换或烧字幕。旧版两阶段描述只供历史追溯，本条和第一阶段专用`BITABLE_WORKFLOW.md`优先。

## v0.4.7：独立纯文案TXT + 飞书多维表第一阶段唯一流程

- **第一阶段强制额外交付 `文案.txt`**：它与 `ClipFlow_完整交付.zip` 是**两个独立文件**，TXT只含原始口播识别台词，每条纯文字一行，无时间轴、片段编号、标题、文件名、Markdown、解释文字；编码UTF-8无BOM，保留语音识别原文正常标点，不套用SRT句尾去标点规则。**TXT绝不加入ZIP**；缺TXT时禁止把完整ZIP当作最终合格交付。
- **飞书Bitable自检是所有新执行窗口的入口门禁**：用户先人为配好飞书多维表CLI/MCP/API中的任一可行通路，AI仍须独立确认**指定表**的记录读取、输入附件真实字节下载、以及ZIP+独立TXT等全部必交产物写入**指定记录同一个成品附件字段**的能力；通用“连接成功”或scope存在不等于已验证目标表可用。
- **表格替代聊天上传**：只从用户固定视图/表的 `备注=未完成` 行领取对标原视频任务，读取真实绑定的原视频附件列，下载并核对原始字节，只执行第一阶段并将**本次所有正式对外交付文件**（包括完整ZIP和ZIP外纯TXT）追加到该行指定多附件格，远端读回且全件齐全后才更新用户批准的状态字段。权限、格式上传（特别TXT）或真实字节验证不通过时HOLD，不要求用户发视频、不改其他记录、不创建新表。用户尚未给表链接/字段映射，不能猜测。
- **后续合并阶段已冻结**：不领取第二阶段任务，不生成合并视频；旧代码仍存在但CLI拒绝调用。去重、锁、幂等与HOLD见第一阶段专用`BITABLE_WORKFLOW.md`；文档不代表已有目标飞书表可写，亦不授权未经绑定的生产试传。
- **同步**：用户本窗口以后更新GitHub后，在同一执行回合同步程序ZIP、规则、样例到已核验的ChatGPT Library `/对标视频处理切割/` 并读回；Space同名目录只有权限真实可用时再同步，不能冒充。

## v0.4.5 视频切分与取帧：正式硬约束

- **三个共同切分准则**：① 每段实际导出时长必须严格大于3.000秒、且不超过8.000秒（包含末段），`--max-seconds` 默认8且不能高于8；② 利用视觉镜头变化作为优选位置；③ 只允许在真实完整语句结束后切分，禁止因镜头转换或8秒上限直接切断讲话。用**未经句末标点清理的原始ASR或用户提供SRT**的可信句终标记判定，结合词级时间戳排除句中/词中切分。SRT字幕条目结束或仅有停顿不等于一句话已经讲完。所有切点使用全片动态规划，避免局部镜头贪心造成尾段<=3秒；遇到长句>8秒、缺可信句尾、总长<=3秒或尾段无法满足条件则生成`cut_conflict.json`并HOLD，不得虚称合格、不生成完整交付ZIP。识别语句完整性是模型辅助推断，仍需抽核。
- **截图新规则**：只从每段原对标MP4开头实际连续前10帧中挑一帧。优先排除黑场、闪白和明显不可用的画面，然后用**Tesseract简体中文OCR**在原画面且尚未叠编号前统计可信可见字符数，按文字字符数最少、文字面积最小、画质清晰度/稳定度和更早帧依次排序。必须具备pytesseract、Tesseract可执行文件和chi_sim/HanS中文语言包，缺失时阻塞而不假报已检测。输出保持原分辨率并叠加与本段MP4一致的左上角C方案001起编号。ZIP前核对每段截图来自前10帧并记录OCR字符数、选中帧序号、语言、同号水印。OCR漏检艺术字是已知限制，不能声称视觉100%准确。

## 第一阶段处理对标视频（默认来自飞书多维表）

默认一并执行原先功能①②③：镜头/人物和对白时间分析、每段严格>3秒且<=8秒并只在完整句终切分、C方案001…编号水印（文本alpha 40%、黑描边alpha80%、横屏10px/竖屏7px），自动生成完整原视频SRT。**首要交付两个独立文件：`ClipFlow_完整交付.zip` 和不入ZIP的 `文案.txt`**，内部包含 segments/ 所有编号MP4、captions.srt、segments_transcript.md（每段一节台词，只在段标题列起止时间）、manifest.json、segments_list.csv、subtitle_samples/（联系表及原帧字幕样张）、subtitle_style_profile.json；以及 `segment_stills/001_镜头.jpg` 等每段一张开头干净截图；旧版两个拆分ZIP仅为兼容保留。程序必须在交付前读回ZIP检查CRC、成员、非空、数量与编号，并仅对真实存在、可下载的文件提供链接。使用 `clipflow reference --input ... --out ...`；先确认ASR可用，否则明确说明需安装依赖/使用用户已校对SRT。不要伪称已经ASR识别。

**SRT导出句末无标点（v0.4.4 强制）**：凡写出 `captions.srt`（第一阶段独立文件、`ClipFlow_完整交付.zip`、`subtitle_reference_stylekit.zip`，以及独立 `clipflow transcribe`），每条字幕的每一行末尾必须去掉句号、问号、感叹号、逗号、省略号、引号等中英文句尾标点及重复标点；正常句中标点可保留。自动语音识别与用户提供的SRT均使用相同的统一 `save_srt` 导出处理。只改SRT显示文本，时间码/编号不变、不得改动分段台词MD与原始转录内容；交付前校验ZIP内SRT同样满足这一规则。

**无画面字幕时的ASR为正式功能**：省略 `--srt` 即从对标视频的原声音轨运行 faster-whisper，优先使用词级时间戳，生成全文SRT并自动按最终分段把台词写进 `segments_transcript.md`（同时写入manifest逐段`transcript`字段）。若没有词级时间戳，或者使用了传入的SRT，则按字幕范围做比例估算并在MD注明。首次安装ASR：`python -m pip install -e '.[asr]'` 或 `python scripts/setup_asr.py --model small`；`clipflow doctor` 可检查依赖是否存在。安装依赖失败/模型不可用/无音轨时明确停止，不编造识别结果。单独语音转文字可用 `clipflow transcribe --input ... --out ...`。不要把“给定SRT”写成“已执行ASR”。

人物身份、机位角度、复杂特效不可能仅靠颜色帧差百分之百判定；需要核对片段和句尾。如果用户要求角色标签，请通过观察/模型判断后写入manifest，不要伪造。

## 历史第二阶段（已冻结）

原有`assemble`合并、调色、换声及字幕压制流程不再由当前程序或任何ClipFlow新窗口执行，正式CLI会拒绝运行。保留其历史源码是为了不误删过去的成果；只有用户将来明确改变范围并发布新版本才重新讨论。下文的字幕样式技术说明仅作为第一阶段**分析对标字幕和生成样张/配置**的历史参考，绝不自动进入字幕压制。

## 对标字幕还原优先规则（高于任何历史固定字模）

- 第一阶段务必查看原视频有无真正的画面字幕（不是单凭音轨或ASR推断）。阅读 `subtitle_samples/subtitle_reference_contact.jpg`，必要时逐张打开同目录**原分辨率截图**；不能确定时追加取样。
- **有字幕**：尽力逐细节复刻：字形/最相似授权字体、粗细、比例字号、字距、显示区域、横纵偏移、单/双行、边框粗细、描边颜色和透明度、阴影、每一条字幕的常规颜色与特殊词颜色/大小、入场退出时机。特别注意颜色按具体字幕变化。不要套用固定C/B/B、84px、黄绿色高亮关键词。
- 用视觉结论填写 `subtitle_style_profile.json`，设 `reference_has_subtitles=true`、`visually_reviewed=true`，按样张配置基础值以及 `caption_styles` 的每条例外。必要时做“对标帧/合成帧”两三组并排校对。字体名字不能直接反推出时，记录近似并使用当地合法可用的最接近字体，不得夸大完全相同。
- **无字幕**：确认后设置 `reference_has_subtitles=false`、`visually_reviewed=true`，允许使用之前的后备方案：特粗黑体或粗宋、普通84px重点94px（以1080竖屏为参照）、白色+黄绿色强调、黑描边、3px字距、中下偏上等。长句缩放防超边。
- **未经视觉审核**：配置中 `reference_has_subtitles=null`、`visually_reviewed=false` 时，禁用字幕合成并提示先审核，禁止悄悄使用B字模。第一阶段做编号ZIP+SRT不受此限制；第二阶段未要求字幕时也不需要审核。
- 如新片段自带硬字幕，不允许二次叠字；如用户要求去掉既有硬字幕，应另行确认处理方案，不能擅自裁切或涂抹。

## 固定设计

- 水印：用户选定C粗描边；不要自动改回B，不要降低40%填充与80%描边alpha。
- 调色：第二阶段后期合并当前已冻结，第一阶段**不做模拟去灰调色**；原视频只做按规则切分和编号。
- 编码：第一阶段保持原视频画幅/输入帧率的合理输出配置，不做60帧高清重制/AI补帧。
- 安全：原素材、字幕、用户音轨只能保留在用户作业目录；禁止提交GitHub。
- 输出：第一阶段首要交付完整ZIP及ZIP外独立`文案.txt`两个文件；ZIP内含分段MP4、SRT、每段一条台词的MD、切分清单、字幕样张。检查ZIP成员、CRC、数量、大小，确认沙箱/附件真实存在后给下载链接；未运行成功不能声称完成。
- **开头截图校验**：执行上文v0.4.5前10帧OCR最少文字规则；从原画面选帧后再叠C方案水印，manifest登记`still_offset_frame_index < 10`、`still_text_characters`、`still_ocr_language`、`still_selection_policy`及三位序号。缺帧或OCR未成功时停止完整ZIP交付，不能回退旧0.6秒/20帧纯清晰度排序。


## 云端ASR执行门禁（v0.4.0）

- **优先复用已获授权的云端ASR服务**：运行环境具有`CLIPFLOW_ASR_URL`与`CLIPFLOW_ASR_API_KEY`时，才允许向这个明确配置的服务上传抽取后的音频块；否则走本地faster-whisper。若用户明确指定本地，使用`--asr-backend local`，不能自动上传。
- 云端只传音频FLAC小块，不传视频画面或整个视频ZIP；密钥放在安全环境变量，禁止存放在GitHub、文档、提示词、常规日志。没有授权域名/密钥/网络时明确报告阻塞，不自行换提供商。
- 第一阶段主交付为经实际解压校验的 `ClipFlow_完整交付.zip`（编号MP4、同号开头截图、句末无标点SRT、逐段台词MD、清单、字幕样张）以及单独的 `文案.txt`；旧版独立ZIP仅兼容保留。本程序当前**不执行第二阶段拼接、调色、换声或烧字幕**。
- **三个层级必须分开验收**：本地代码及协议测试、云端模型实际部署与受保护访问、真实中文口播转写及SRT/逐段MD验证。付费计划/密钥配置/跨账号授权需要相应批准。不能把模拟测试称为真实Whisper或生产就绪。
