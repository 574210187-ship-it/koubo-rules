# AI 窗口汇报执行规范

协议版本：`1.0.0`

你正在执行一个项目任务。发起人会在启动指令中提供目标飞书多维表、目标子表和可能的 `table_id`。本文件是本次汇报的完整执行规范。

## 1. 先确认目标

目标子表应为：`汇报项目`。

如果启动指令没有提供目标飞书多维表，停止写入并请求目标链接。不要猜测目标，不要使用其他聊天中见过的链接。

如果执行环境提供飞书多维表 MCP、CLI 或 API，优先使用它们写入并回读。不要在没有回读证据时声称已经写入。

## 2. 什么时候必须汇报

出现以下任一情况时提交：

1. 到达约定汇报时间；
2. 本轮任务完成；
3. 取得阶段性结果；
4. 出现阻塞、失败或需要用户协助；
5. 以前的问题已经恢复；
6. 需要更正上一条汇报。

普通心跳或没有任何变化的重复状态，不需要制造新汇报，除非发起人明确要求定时提交。

## 3. 一行只能有一次汇报

- 一个窗口的一次执行结果，只新增一行。
- 一个窗口的一次问题，只新增一行。
- 下一轮执行、重试、纠正、问题恢复，都必须再新增一行。
- 禁止覆盖或追加修改旧行。
- 禁止把多个汇报标题、多个归档标识或多个汇报时间写进同一个“执行记录”单元格。
- WorkBuddy 的执行结果和 ChatGPT/Codex 的验收结果分别新增一行。
- 同一次执行既有结果又有独立问题时，分别新增“结果”行和“问题故障”行。

## 4. 固定填写的单元格

每一行必须填写：

| 单元格 | 规则 |
| --- | --- |
| `/提交日期` | 本次实际汇报日期，使用北京时间 |
| `/是否启动` | 执行中、阶段性完成、阻塞、失败待处理、等待用户=`是`；真正完成、关闭、终止=`否` |
| `任务名称` | 本次执行的一个具体任务 |
| `工具` | ChatGPT、Codex 或 WorkBuddy |
| `所属项目` | 项目固定名称 |
| `电脑名称` | 实际执行电脑；云端可填“Codex云端” |
| `类型` | 只能是`结果`或`问题故障` |
| `进度` | 使用第5节或第6节固定格式 |
| `阶段` | 当前业务阶段；确实无法确认时填“未确认” |
| `描述` | 使用第5节或第6节固定格式 |
| `执行记录` | 只写本次汇报，使用固定模板 |

`/最后更新时间`由系统记录或使用实际提交时间。

`项目ID`、`机器ID`、`项目本地根目录`有可靠现成值时填写；不知道时留空，禁止猜测。

## 5. 结果汇报

正常执行、阶段性进展、完成任务或问题恢复时，`类型`填写`结果`。

`进度`格式：

```text
完成判定｜完成量/目标量｜剩余量｜一句结论
```

没有数字目标时：

```text
完成判定｜无量化目标｜一句结论
```

完成判定只能使用：`完成`、`阶段性完成`、`未完成`、`问题已恢复`。

`描述`格式：

```text
本次完成：……
未完成：……
下一步：……
```

`执行记录`使用 [`templates/result-report.md`](templates/result-report.md)。

声称`完成`时，验收证据不能为空。已开始、已安排、已入池、正在运行不等于完成。

## 6. 问题故障

发生失败、阻塞、长期无进展或需要用户处理时，`类型`填写`问题故障`。

`进度`格式：

```text
阻塞/失败/等待用户｜影响对象｜一句结论
```

`描述`格式：

```text
问题：……
影响：……
已尝试：……
需要你：无/具体操作
```

`执行记录`使用 [`templates/problem-report.md`](templates/problem-report.md)。

同类问题必须复用相同的`问题代码`。不要为了逃避重复问题统计而更换代码。

## 7. 更正与恢复

更正旧汇报时新增一行，不修改旧行，并在执行记录中写：

```text
更正对象：原飞书record_id
更正内容：……
更正原因：……
```

问题恢复时新增一条`结果`行，完成判定填写`问题已恢复`，并写：

```text
关联问题代码：……
恢复结果：……
恢复证据：……
```

## 8. 提交前强制自检

提交前逐项确认：

1. 当前行只有一次汇报；
2. 只有一个汇报标题和一个执行时间或发生时间；
3. 没有复制历史汇报；
4. 固定单元格已经填写；
5. 类型与内容一致；
6. 完成量、目标量和剩余量一致；
7. 声称完成时存在验收证据；
8. 问题行包含稳定的问题代码；
9. 问题行明确写了`需要你：无`或具体操作。

自检不通过时先修正，不得提交。

## 9. 写后回读

写入后必须重新读取刚创建的记录，核对关键字段，并取得飞书 `record_id`。

最终回复发起人时只需简短说明：

```text
已新增1条结果汇报/问题汇报。
record_id：……
状态：写入并回读通过
```

如果无法读取本规范、没有写入权限、连接失败或回读失败：

- 不得声称已经提交；
- 说明具体错误和缺少的权限；
- 输出全部待提交字段，供其他工具代写；
- 不要把密钥、OAuth token、Webhook key 或 Cookie 输出到聊天或公开仓库。
